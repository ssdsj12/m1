MPC 接入 RL 的参与环境选择、运行时优化与语义真实碰撞设计

日期：2026-05-30 ｜ 主线：MPC semantic trajectory reward ｜ 文件范围： Go2Pvcnn/extension/batch_mpc_planner、 Go2Pvcnn/extension/mdp/rewards_reference.py、 Go2Pvcnn/go2_pvcnn/tasks/teacher_elevation_trajectory_mpc_semantic_env_cfg.py

1. 设计目标

把当前 MPC reference 接入 RL 训练时，不让所有环境都参与 MPC 规划。只允许用户配置范围内的环境进入 MPC 抽签；当前明确隔离的地形和难度组合不参与 MPC，其余环境仍可以参与抽签。

未被选中的环境不调用 MPC，不更新新的 MPC reference，其 MPC reference reward 返回 0。基础 locomotion reward、速度跟踪、碰撞惩罚等其他 reward 不受影响。

不变约束：本设计不修改 low-small loss 公式，不新增 optimizer loss，不新增硬约束，不改变 decode_parametric_trajectory() 的职责。2026-05-28 low-small 设计效果不能回退。

1.1 当前状态

模块状态说明
MPC 参与环境选择已完成只对选中 env 规划，未选中 env 的 MPC reference reward 返回 0；支持 include、exclude pair 的 AND 逻辑和 round-robin 抽样。
25 step 对齐已完成MPC horizon、reference cache horizon、replan interval 已按 25 step 对齐。
世界坐标足端 tracking已完成MPC reference 足端和 IsaacLab 当前足端均使用 world frame；reward 使用 manager frame id，避免 episode modulo 错位。
旧 per-body filtered ContactSensor 方案待替换当前实现会把 /World/semantic_course/small/.* 转成一级 glob，导致 PhysX 报 expected 1024, found 7/5；该方案不再作为目标设计。
新语义真实碰撞方案待实现采用 2 个继承自 IsaacLab ContactSensor 的全局语义 contact sensor：small 一个、large 一个；sensor 内部覆盖所有指定 robot body 和该语义类别下全部真实 slot_* 物体。

2. 25 帧对齐约束

MPC 规划帧数、reference cache 帧数和重规划周期必须对齐：

MPC horizon = reference cache horizon = replan interval = 25

任务配置需要显式设置：

reference_trajectory_horizon = 25
reference_replan_interval_steps = 25

MpcRuntimeCfg.horizon_steps 默认已经是 25。由于 planner_cfg_from_task_cfg() 会用 reference_trajectory_horizon 覆盖 runtime.horizon_steps，MPC semantic 任务必须显式覆盖父类默认值 50。

验收检查：

manager.horizon_steps() == 25
cache.horizon_length() == 25
cfg.reference_replan_interval_steps == 25

3. 参与环境选择函数

新增一个纯 selector 函数。它只判断哪些 env 本次允许参与 MPC，不做规划、不写 cache、不计算 reward。

建议位置：

Go2Pvcnn/extension/batch_mpc_planner/participation.py

函数接口：

select_mpc_reference_envs(
    *,
    num_envs: int,
    device: torch.device,
    terrain_types: Tensor | None,
    terrain_levels: Tensor | None,
    terrain_names: list[str] | None,
    cfg: MpcReferenceParticipationCfg,
    sample_count: int,
    cursor: int,
) -> tuple[Tensor, int]
输入含义
num_envs总环境数。
device输出 mask 所在设备。
terrain_typesshape 为 [num_envs]，IsaacLab terrain col / 地形类型 id。
terrain_levelsshape 为 [num_envs]，IsaacLab terrain row / 难度 id。
terrain_namescol id 到 terrain name 的映射，来自 terrain.cfg.terrain_generator.sub_terrains。
cfg用户可调参与规则。
sample_count本次最多选择多少 env 参与 MPC。
cursorround-robin 当前游标。

函数输出：

selected_mask: Tensor  # shape [num_envs], dtype bool
next_cursor: int

selected_mask[i] == True 表示第 i 个 env 本次参与 MPC 规划，并且后续 25 step MPC reference reward 生效。False 表示本次不参与 MPC，MPC reference reward 为 0。

5. 隔离规则：地形和难度是 AND 逻辑

用户希望隔离的环境必须同时满足“指定地形”和“指定难度”，才会被排除。只满足地形或只满足难度的环境，仍然需要参与抽签。

excluded(env) = terrain_match(env) AND row_match(env)

例子：

exclude_pairs = [
  {
    terrain_names = ("stairs_down", "rough_large"),
    terrain_rows = (7, 8, 9),
  }
]
env 情况是否排除原因
terrain 是 stairs_down，row 是 8排除地形和难度同时命中。
terrain 是 stairs_down，row 是 3不排除只命中地形，没有命中难度。
terrain 是 flat，row 是 8不排除只命中难度，没有命中地形。
terrain 是 flat，row 是 3不排除地形和难度都未命中。

如果 include_terrain_* 或 include_terrain_rows 被设置，它们先定义“允许参与抽签的大范围”；然后 exclude_pairs 在这个范围内按 AND 逻辑扣掉坏组合。

eligible(env) = include_match(env) AND NOT any_pair_excluded(env)

6. 轮转抽样

从 eligible_ids 里使用 round-robin 抽样，而不是每次随机抽样。

eligible_ids = 满足参与规则的 env ids selected_ids = eligible_ids[cursor : cursor + sample_count] 如果越过末尾，则 wrap around next_cursor = (cursor + sample_count) % len(eligible_ids)

好处是每个符合条件的 env 都会周期性拿到完整 25-step MPC reference，显存由 sample_count 控制，reward 覆盖稳定，日志更容易解释。

7. Manager 调用流程

MpcTrajectoryManager.refresh_from_env() 的流程调整为：

1. 每 25 step 触发一次 global_due
2. 从 IsaacLab terrain 读取：
   - terrain.terrain_types
   - terrain.terrain_levels
   - terrain.cfg.terrain_generator.sub_terrains names
3. 调 select_mpc_reference_envs(...)
4. 只对 selected_ids 构建 state / command / terrain subset
5. 只对 selected_ids 调 plan_segment(...)
6. selected_ids 的结果写入 full-shaped cache
7. reference_reward_mask = replace_mask
8. 未选中 env 的 reference reward 为 0

reward 侧已有 reference_foot_pos_reward() 乘 manager.reference_reward_mask() 的逻辑，因此未参与 env 不需要额外 reward 分支。

8. 训练信号密度

为了让模型学会轨迹，MPC reward 不能太稀疏。建议监控：

duty_cycle = selected_env_count / eligible_env_count

第一版建议 duty_cycle >= 0.25。例如：

eligible_env_count = 512
selected_env_count = 128
duty_cycle = 25%

未参与 env 只是不拿 MPC reference reward，其他基础训练信号仍然存在。

9. 显存和速度优化边界

第一版只做不改变 low-small 优化结果的优化：

  • 只规划 selected env。
  • horizon / replan / cache 全部对齐到 25。
  • 训练期关闭 CUDA sync profiling。
  • 优化结束后的 cache/export/FK 写回使用 detach 或 torch.no_grad()。
  • steps > 0 时，不再保留 Adam loop 前那次冗余 sampled loss 计算。
mpc_diagnostics_emit_runtime_counters = False
mpc_diagnostics_profile_cuda_sync = False

以下优化暂不做，因为可能改变 low-small 效果：

  • 减少 optimize_steps。
  • 让 FK collision / touchdown keepout 等 heavy loss 隔步计算。
  • AMP / float16。

10. reference_foot_pos_reward 世界坐标系跟踪

reference_foot_pos_reward() 需要改成世界坐标系下的足端跟踪。IsaacLab 当前足端和 MPC reference 足端都必须是 world frame。

当前真实足端：

current_foot_w = asset.data.body_pos_w[:, foot_body_ids, :]

MPC reference 足端：

ref_foot_w = cache.foot_pos_w[env_id, frame_id]

reward 公式：

err_e = mean_l || current_foot_w(e,l) - ref_foot_w(e,l) || R_foot(e) = exp( - err_e / sigma^2 ) * reference_reward_mask(e)

因此 ReferenceTrajectoryCache 需要新增字段：

foot_pos_w: Tensor | None = None

旧字段 foot_pos_root 第一版保留，用于兼容 together/legacy/已有测试；新的 MPC semantic foot tracking reward 读取 foot_pos_w。

同时，MPC backend 的参考帧选择需要使用 manager 自己维护的 phase：

frame_ids = manager.current_frame_ids()

而不是继续使用：

frame_ids = env.episode_length_buf % horizon

原因是 selected env 在任意 episode step 重新规划时，cache 第 0 帧对应当前状态；如果用 episode modulo，会出现当前真实足端追未来帧 reference 的错位。

11. 基于 IsaacLab 真实 contact 的语义碰撞 reward

当前 swing_leg_collision_reward() 基于 semantic_height_scanner 查询 height/semantic，这会受 scanner 更新周期和栅格分辨率影响。新的 RL 语义碰撞 reward 改为使用 IsaacLab / PhysX 的真实接触力。

旧实现尝试为每个 body、每个语义类别创建一个 filtered ContactSensorCfg，并直接使用 /World/semantic_course/small/.* 作为 filter。该路径在 IsaacLab 内部会被转成一级 glob /World/semantic_course/small/*，只匹配到 row_* 一级目录，不会覆盖真正的 row_*/col_*/slot_* leaf obstacle，并且会触发 PhysX 数量对齐错误。

废弃方案：不再使用 26 个 per-body scene sensor，不再让默认 IsaacLab ContactSensor 直接消费 /World/semantic_course/*/.*。该方案会出现 expected 1024, found 7/5，不能作为训练 reward 的真实碰撞来源。

新方案采用 2 个自定义 sensor，均继承 IsaacLab ContactSensor，但覆盖 contact view 初始化逻辑：

semantic_contact_small  # 所有指定 robot body 对所有 small slot_* 物体
semantic_contact_large  # 所有指定 robot body 对所有 large slot_* 物体

外层仍通过 IsaacLab scene cfg 注册，reward manager 仍按标准 IsaacLab RewTerm 调用。底层 PhysX view 的路径展开和数量对齐封装在自定义 sensor 内部。

11.1 自定义 sensor 位置和职责

新增目录：

Go2Pvcnn/go2_pvcnn/sensor/semantic_contacter/

建议文件：

__init__.py
semantic_global_contact_sensor.py

核心类：

class SemanticGlobalContactSensor(ContactSensor): ...

职责：

  • 继承 IsaacLab ContactSensor 的 lazy update、data、reset、debug_vis 外部接口。
  • 在初始化时解析 prim_path 对应的所有指定 robot body leaf prim。
  • 在初始化时递归解析 filter_prim_paths_expr 对应的全部真实 semantic leaf obstacle，不允许只匹配 row_*。
  • 创建 PhysX RigidContactView 时使用 exact sensor path list 和 per-sensor filter path list，保证数量对齐。
  • 输出 data.force_matrix_w，shape 固定为 [num_envs, num_bodies, num_semantic_objects, 3]。

11.2 Scene 配置

scene 中只保留两个 semantic contact sensor：

semantic_contact_small = ContactSensorCfg(
    class_type=SemanticGlobalContactSensor,
    prim_path="{ENV_REGEX_NS}/Robot/.*",
    filter_prim_paths_expr=["/World/semantic_course/small/.*"],
    ...
)

semantic_contact_large = ContactSensorCfg(
    class_type=SemanticGlobalContactSensor,
    prim_path="{ENV_REGEX_NS}/Robot/.*",
    filter_prim_paths_expr=["/World/semantic_course/large/.*"],
    ...
)

prim_path="{ENV_REGEX_NS}/Robot/.*" 只表示从 robot 下收集候选 body。实际参与 contact reward 的 body 必须由 sensor 参数或常量限制为：

FL_foot, FR_foot, RL_foot, RR_foot
FL_calf, FR_calf, RL_calf, RR_calf
FL_thigh, FR_thigh, RL_thigh, RR_thigh
base

body 顺序必须稳定，并与 SEMANTIC_CONTACT_BODY_WEIGHTS 一一对应。

11.3 数量对齐

以 num_envs=1024、num_bodies=13 为例，sensor 初始化后应满足：

small_sensor.contact_physx_view.sensor_count = 1024 * 13 large_sensor.contact_physx_view.sensor_count = 1024 * 13 small_sensor.contact_physx_view.filter_count = N_small_slot large_sensor.contact_physx_view.filter_count = N_large_slot

其中：

N_small_slot = count(/World/semantic_course/small/row_*/col_*/slot_*) N_large_slot = count(/World/semantic_course/large/row_*/col_*/slot_*)

读取数据后必须 reshape 为：

small_force_matrix.shape = [1024, 13, N_small_slot, 3] large_force_matrix.shape = [1024, 13, N_large_slot, 3]

11.4 Reward 公式和 IsaacLab 接口

reward 仍封装成 IsaacLab RewTerm 可消费的函数：

semantic_global_contact_collision_reward(
    env,
    small_sensor_cfg: SceneEntityCfg,
    large_sensor_cfg: SceneEntityCfg,
    body_names: tuple[str, ...],
    body_weights: tuple[float, ...],
    force_threshold: float,
    force_scale: float,
    force_clip: float,
    small_weight: float,
    large_weight: float,
) -> Tensor

scene cfg 示例：

semantic_contact_collision = RewTerm(
    func=semantic_global_contact_collision_reward,
    weight=1.0,
    params={
        "small_sensor_cfg": SceneEntityCfg("semantic_contact_small"),
        "large_sensor_cfg": SceneEntityCfg("semantic_contact_large"),
        "body_names": SEMANTIC_CONTACT_BODY_NAMES,
        "body_weights": SEMANTIC_CONTACT_BODY_WEIGHTS,
        "force_threshold": 1.0,
        "force_scale": 50.0,
        "force_clip": 1.0,
        "small_weight": 1.0,
        "large_weight": 2.0,
    },
)

reward 不创建 PhysX view，不遍历 USD stage，只从 scene 读取两个 sensor：

small = env.scene["semantic_contact_small"].data.force_matrix_w
large = env.scene["semantic_contact_large"].data.force_matrix_w

公式：

P_small(e,b) = Σ_o ReLU(||F_small(e,b,o,:)|| - F_threshold) P_large(e,b) = Σ_o ReLU(||F_large(e,b,o,:)|| - F_threshold) P(e) = Σ_b w_body(b) * [w_small * P_small(e,b) + w_large * P_large(e,b)] R_collision(e) = -clamp(P(e) / F_scale, 0, F_clip)

reward 输出必须是 [num_envs]，device 与 env device 一致，不允许 NaN/Inf。

13. Low-small 不变项

为了保证 2026-05-28 low-small 设计效果不变，以下内容保持不变：

  • decode_parametric_trajectory() 只消费 nominal + variables。
  • 不新增 touchdown hard projection。
  • 不新增 touchdown snapping。
  • 不新增足端硬分离。
  • 不新增 optimizer loss。
  • 第 0 条 low-small FK semantic collision probe 仍然只作为优化后诊断。
  • 现有 low-small loss 集合和公式不变。

13.1 PLAY / VIEWER 配置拆分

scripts/play.py 和 extension/viz/go2_foostep_planner.py 不能继续共用同一个带 MPC 的 PLAY 配置。普通 policy playback 只需要 observation/action 推理链路，不需要 MPC reference cache、trajectory manager 或 25-step replan；viewer 则需要保留当前 MPC 可视化和规划行为。

配置类消费者MPC 行为设计要求
TeacherElevationTrajectoryMpcSemanticEnvCfgscripts/train.py开启训练主配置保持当前 25-step MPC、64 个参与 env、semantic contact reward 和 reference reward 行为。
TeacherElevationTrajectoryMpcSemanticEnvCfg_PLAYscripts/play.py关闭只给普通 RL policy playback 使用；planner_owned_reference_cache=False，use_batched_reference_trajectory=False，不得 attach MPC trajectory manager。
TeacherElevationTrajectoryMpcSemanticEnvCfg_VIEWERextension/viz/go2_foostep_planner.py开启只给 MPC viewer 使用；保留当前 PLAY 中已有的 MPC、diagnostics、n_frames、plan_dt 和可视化调试行为。

Gym 的 Isaac-Teacher-Elevation-Trajectory-Mpc-Semantic-Go2-Play-v0 继续指向 TeacherElevationTrajectoryMpcSemanticEnvCfg_PLAY。viewer 不复用这个 play env id，而是在自己的 _build_env_cfg() 中直接构建 TeacherElevationTrajectoryMpcSemanticEnvCfg_VIEWER。

关闭 PLAY 的 MPC 后，policy playback 仍必须保留策略观测需要的 semantic height scanner、command、action 和基础 IsaacLab step 链路。若 reward manager 在 play 中仍会计算 reward，MPC reference reward 必须在无 trajectory manager 时返回 0 或被配置关闭，不能因为缺少 MPC cache 使 policy playback 崩溃。

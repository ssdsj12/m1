Go2 几何体语义 clearance reward 设计

日期：2026-06-11 ｜ 主线：T302q flat-small avoidance ｜ 范围： semantic_body_part_clearance_reward 的下一版几何体拟合设计

1. 背景和问题

当前 flat-small 训练中，semantic_contact_collision 有稀疏碰撞信号， 但新增的 semantic_body_part_clearance 在 TensorBoard 中全程为 0。 这不是物理接触传感器失效，而是当前 clearance reward 只查询 foot/calf/thigh 的少量中心采样点； 如果这些点没有刚好落到 scanner semantic map 的 small cell 上，就不会产生任何惩罚。

目标：把 clearance reward 从“点命中”改成“几何包络邻域命中”。 它仍然只使用当前 IsaacLab 机器人姿态和当前 scanner elevation/semantic map，不修改 MPC reference、MPC loss 或 contact sensor。

2. USD 尺寸依据

本设计参考本地 Go2 USD： assets/teacher_object/Robots/Unitree/Go2/go2.usd 和 assets/teacher_object/Robots/Unitree/Go2/Props/instanceable_meshes.usd。 项目配置中的 Go2 资产入口位于 Go2Pvcnn/go2_pvcnn/assets/__init__.py。

部件 USD 证据 设计解释
foot collision sphere radius = 0.022m；visual size 约 0.045 x 0.040 x 0.039m 真实 foot 可以直接按 sphere 近似，但 reward 查询半径应略膨胀，用于提前避障。
thigh collision cube full size 约 0.213 x 0.0245 x 0.034m；visual size 约 0.097 x 0.073 x 0.278m collision cube 很瘦；为了训练信号不漏检，reward 几何应取 collision 和 visual 之间的保守半径。
calf visual size 约 0.058 x 0.040 x 0.267m；未读到有效 collision primitive 小腿是小障碍碰撞的主要部位，采用 capsule，半径参考 visual 横截面半对角并稍微膨胀。
base collision box full size 约 0.376 x 0.0935 x 0.114m；visual size 约 0.460 x 0.194 x 0.186m base 用 oriented footprint box 近似，reward 半尺寸略大于 collision box 但小于 visual box。

关节 / link 原点还给出腿部长度约束：thigh 到 calf 约 0.213m， calf 到 foot 约 0.213m，foot 总 z 约 -0.426m。

3. 几何拟合方案

部件 几何体 轴线 / 位置 建议参数 用途
foot sphere 每个 foot body center physical_radius=0.022m；query_radius=0.035m 检测足端或足端附近是否接近 small obstacle，避免 swing foot 扫到障碍。
calf / shank capsule calf body center -> foot body center capsule_radius=0.040m；query_radius=0.045m；sections=7 主避障对象；小障碍最容易撞到这里。
thigh capsule thigh body center -> calf body center capsule_radius=0.040m；query_radius=0.045m；sections=7 辅助避免较高 small obstacle 或腿摆动过低。
base oriented footprint box root pose 下的 body-frame box footprint half_x=0.20m；half_y=0.06m；half_z=0.07m；grid=5x3；query_radius=0.03m 防止底盘擦碰 small obstacle，权重低于 calf，避免过度抬身。
重要解释： sections=7 不是退回“7 个点检测”。每个 section 是 capsule 轴线上的一个横截面圆盘； 每个圆盘再查半径邻域内的 semantic/elevation cells。7 个圆盘的并集近似一条 capsule 的投影覆盖区域。

4. 地图查询模型

scanner 提供的是离散二维 map： 

semantic_map:  [N, H, W]
elevation_map: [N, H, W]

因此 reward 不需要做 USD mesh 与 capsule 的连续相交。每个几何体转换成一组固定数量的 world-frame query_xy，再通过现有 MPC terrain query helper 一次性读取 semantic id 和 height。

small_mask = semantic_at(terrain, query_xy) == 1 obstacle_z = max(height_at(terrain, query_xy) where small_mask) body_surface_z = primitive_center_or_section_z - primitive_vertical_radius deficit = relu(obstacle_z + margin - body_surface_z) penalty = deficit^2

如果一个几何体的邻域没有 small semantic cell，则该几何体在该 env 上的 penalty 为 0。 如果有 small semantic cell，但 body surface 已经高过障碍高度加 margin，也为 0。

5. 并行和速度设计

训练 hot path 必须固定 shape、全 GPU batch，不允许 per-env Python loop，不遍历 USD prim，不做 CPU 几何库。 所有 query 先拼成规则张量，再调用一次或少数几次 semantic_at() / height_at()。 

# 概念 shape
query_xy: [N, total_queries, 2]
semantic: [N, total_queries]
height:   [N, total_queries]
策略 做法 收益
固定查询数量 foot / calf / thigh / base 的 section 数、邻域 offset 数都固定 避免 ragged tensor 和动态分支，便于 PPO 稳定运行。
offset 缓存 每个半径的圆盘 offset 在第一次调用时缓存到 device 上 每步只做中心点加 offset，不重复 meshgrid。
按部件分组 必要时 foot、leg、base 分三组 query 控制 grid_sample 临时张量大小，便于 profile。
GPU reduce 使用 any、max、sum 做 per-part / per-env 聚合 避免 Python 聚合循环。

5.1 查询规模估算

第一版建议把圆盘 offset 控制在 K=13 左右： 

foot:  4 legs * 1 section * 13 = 52 queries/env
calf:  4 legs * 7 sections * 13 = 364 queries/env
thigh: 4 legs * 7 sections * 13 = 364 queries/env
base:  15 footprint samples * 9-13 = 135-195 queries/env

total: 约 915-975 queries/env

1024 env 时约 94 万到 100 万 query 点。这个数量比旧的 20 点多很多， 但它是固定 shape 的 GPU grid sampling，不应退化成 Python 循环。 如果 profile 显示过慢，优先降低 K 或 base footprint 密度，而不是改变数据流。

6. Reward 聚合

推荐把各部件 penalty 先分别算成 [N]，再加权聚合： 

reward = -clip(
    foot_weight  * foot_penalty
  + calf_weight  * calf_penalty
  + thigh_weight * thigh_penalty
  + base_weight  * base_penalty,
  0.0,
  penalty_clip,
)
部件 初始权重 说明
foot 0.5 避免过度惩罚正常落脚；swing foot 可以后续加高权重。
calf 2.0 主要避障对象，优先保证小腿绕过 low-small。
thigh 1.5 防止腿部上段低扫障碍，但不要超过 calf。
base 1.0 防止底盘擦碰；若出现过度抬身或保守绕行，优先降低 base 权重。

7. 验证计划

阶段 验证内容 通过标准
纯张量测试 构造 semantic/elevation map，验证 sphere、capsule、base footprint 能在邻域覆盖 small cell 时产生 penalty 旧点采样漏检的 fixture，新几何 reward 非 0。
shape / 性能测试 1024 env 模拟 map 和 body pose，检查 query tensor shape 和耗时 无 per-env loop；输出 shape 为 [N]；无 NaN/Inf。
真实 IsaacLab probe flat-small 64/1024 env，读取 scanner map、body pose、reward 非零率 scanner 有 small id 且几何邻域靠近障碍时 reward 能触发。
短训练 TensorBoard resume checkpoint 跑短训，观察 semantic_body_part_clearance 该项不再全程为 0；不显著拖慢 collection。

8. 风险和边界

不要做： 不做真实 mesh-capsule 相交，不遍历每个障碍物 prim，不在 reward hot path 中调用 USD/PhysX 几何查询。
  • 如果 query 半径过大，策略可能过度保守，表现为绕行过度或抬腿过高。
  • 如果 base 权重过高，可能诱导机器人抬身或改变正常 gait；base 初始权重应低于 calf。
  • 如果 K 太大，grid_sample 会成为新瓶颈；第一版优先用 K=13。
  • 该 reward 仍然是 scanner-map 近似，不替代真实 semantic_contact_collision。

  capsule_radius_m: 0.040
  query_radius_m: 0.045
  sections: 7

  half_extents_m: [0.20, 0.06, 0.07]
  footprint_grid: [5, 3]

  neighbor_offsets: cached per radius
  penalty_clip: 1.0
  no per-env Python loop

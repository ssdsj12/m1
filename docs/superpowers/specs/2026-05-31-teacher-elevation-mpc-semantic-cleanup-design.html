配置继承链压平

当前 teacher_elevation_trajectory_mpc_semantic_env_cfg.py 依赖旧 teacher cfg 父类。清理时不能直接删除父类文件，必须先把当前主线真正需要的字段搬进 semantic MPC 当前模块，或搬到一个只服务当前主线的 compact base。

需要保留的配置 处理方式
robot asset、terrain importer、contact_forces、sky light 复制到当前 semantic MPC scene cfg 或当前主线 base cfg。
commands、actions、events、terminations、curriculum 只保留当前训练需要的项，删除旧 experiment 专用项。
semantic terrain generator 保留当前 small/large semantic course 布局和 semantic id 约定。
observations 只保留 policy/critic 的 elevation_semantic_map 和 state 观测。
rewards 只保留当前 locomotion 基础 reward、world foot reference reward、semantic contact collision reward。
MPC cfg 保留当前 MpcPlannerCfg，horizon/replan 对齐到 25。

压平顺序要求

  1. 先让 semantic MPC cfg 不再 import 旧 teacher cfg。
  2. 再收窄 train.py、play.py、register_envs.py。
  3. 最后删除旧 cfg 文件。

不能反过来先删旧 cfg，否则当前 cfg import 链会断，无法用测试定位真实回归。

batch_mpc_planner 内部清理设计

生产包保留内容

文件 保留理由 清理要求
config.py MPC runtime / loss / diagnostics cfg。 删除旧 loss cfg、旧 debug variant 字段、旧 dense/legacy/together 兼容字段。
manager.py RL selected-env planning、reference cache 写入。 保留必要 runtime counter；非必要 debug print 移到 tests。
planner.py plan_segment() 主流程。 删除 debug_loss_variant 消费；删除 probe-only loss；减少重复 terrain/IK/FK 查询。
parametric.py 变量初始化和 decode。 保持 decode 只消费 nominal + variables + optimized command，不做额外策略逻辑。
parametric_losses.py 当前 optimizer loss。 只保留已确认 loss；删除旧 loss 和未启用路线。
semantic_policy.py nominal 构建和高大障碍物 command shaping。 作为策略前处理层，不把优化 loss 放进这里。
semantic_geometry.py low-small GPU circle 构建。 保留 GPU 实现；避免 CPU component 拟合。
terrain.py height / semantic query、scanner terrain 构建。 缓存可复用中间值，避免同一批采样点重复查询。
kinematics.py IK/FK、body/knee/shank/foot 点。 统一 FK 结果供多个 loss 使用，避免每个 loss 重算。
adapter.py、types.py、participation.py viewer/RL/cache 边界结构。 只保留 semantic MPC 所需字段。

迁移或删除内容

  • debug_variants.py：迁移到 Go2Pvcnn/tests 或删除；生产 planner 不再 import。
  • profiles.py / profiling.py：如果只服务调试打印，迁到 tests；如果 train runtime counter 还需要，则保留最小版本。
  • losses/ 子包：如果当前 parametric path 不再使用，删除；如果某些函数仍被 tests/probe 引用，需要迁到 tests helper 或并入当前 loss 文件。
  • 旧 dense/legacy/together 对齐断言、旧 mode 字段检查、旧 T116/T300/T302h 复现实验代码：不放在生产 planner 包。

重复计算清理点

重复项 目标处理
同一批 foot/root/body/knee/shank 采样点重复调用 height_at / semantic_at 在 optimizer loss 入口统一采样和查询，再把结果传给各 loss。
low-small circle 在多个 loss 或 probe 中重复构建 每次 plan 对 terrain 构建一次，作为 loss context 复用。
IK/FK 在 FK collision、FK consistency、post metrics 中重复求 统一生成 FK realized trajectory context，loss 共享。
touchdown sample / swing arc sample 重复构造 把采样点作为 parametric decode 或 loss context 的明确输出。
diagnostics 为了 breakdown 重新算一遍 loss 训练默认不额外算；viewer 或 test 需要时才开启。

  • 不能把 debug/probe-only 逻辑留在 extension/batch_mpc_planner 热路径。
  • 不能删除 semantic raycaster 或 semantic contactor 的当前验收能力。
  • 不能修改 IsaacLab 源码。

测试和验收边界

保留测试类别

  • 当前 train 命令 smoke。
  • 当前 play/viewer import 或短步 smoke。
  • MPC planner 单测：只保留当前 batch_mpc_planner 主线相关部分。
  • low-small 验收 probe：语义圆、swing clearance、FK body/leg collision、FK consistency、plane root-z。
  • RL participation/reward：25 horizon/replan、selected env、world-frame foot reward。
  • semantic contact：small/large 数量对齐、真实 drop probe、无 NaN/Inf、无 env 串扰。
  • semantic raycaster smoke：semantic_height_scanner 输出高程+语义 grid。

新增清理验收

  • extension/batch_mpc_planner 不再包含 probe-only/debug-only 文件。
  • plan_segment() 不再消费 debug_loss_variant。
  • 生产代码不再 import batched_planner 或 batched_together_planner。
  • 生产代码不再 import 旧 teacher experiment cfg。
  • 1024 env / 64 MPC env / 25 step 性能不慢于当前可接受基线；目标仍小于 10 秒/epoch。

建议执行顺序

  1. 冻结 golden tests 清单，先确认当前 HEAD 上测试能跑。
  2. 压平 semantic MPC cfg 的继承链，让当前 cfg 自包含。
  3. 收窄 train/play/register/factory 入口到唯一 experiment 和唯一 backend。
  4. 迁移或删除 batch_mpc_planner 里的 debug/probe-only 代码。
  5. 删除旧 backend 目录和旧 experiment cfg。
  6. 清理 tests：旧测试删除或改成当前主线测试，probe helper 放在 Go2Pvcnn/tests。
  7. 做重复计算优化，但每个优化都必须用 loss/effect/performance 验证，不和大规模删除混在一起。
  8. 运行完整验收，更新 todo/log/文档。

需要用户确认的设计点

本设计默认采用“先压平继承和收窄入口，再删除旧代码，最后做重复计算优化”的顺序。这样能把行为回归和结构清理分开定位。

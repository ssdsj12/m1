# T500 SO(3) 修复与 10,000 步多 GPU 验证设计

## 目标

修正 T500 双 Panda + 双 O6 控制链中右掌姿态参考的表示不一致，使轨迹插值、空间姿态误差、角速度前馈和 Arm MPC 使用同一套 SO(3) 语义。使用服务器空闲 GPU 4–7 完成总计恰好 10,000 个 Isaac Sim 物理步的门控验证，并用最佳安全配置采集 teacher 数据供离线 latent/MPC 模型训练。

本轮不把 10,000 步结果等同于最终 30/30 验收。正式验收仍要求 seeds 42/43/44，各 10 次完整夹持、抬升 0.10 m、保持 3 s、下降和释放全部通过。

## 修复边界

- 只修改 `Go2Pvcnn/go2_pvcnn/control/m1_bimanual_coordination/` 内 T500 姿态适配相关代码及其测试、诊断字段。
- 使用 `Log(R_target R_measured.T)` 计算空间姿态误差，不直接相减 rotation vector 坐标。
- 使用 SO(3) 插值生成节点姿态，并从相邻旋转的对数映射计算与空间 Jacobian 一致的角速度前馈。
- 保留现有公开 dataclass 字段、43 通道排序、25/50/100/200 Hz 调度和安全回退合同。
- 不改变箱体几何、机械安装位姿、关节限位或验收阈值；如修复后仍失败，再单独设计跟踪感知的一节点边界。

## 测试与步数账本

总预算严格为 10,000 个仿真步。

1. 候选筛选：4 个候选配置分别在 GPU 4–7 上运行 350 步，共 1,400 步。候选只改变姿态适配的受控参数，不改变几何或安全阈值。
2. 跨 seed 物理门：选择唯一最佳候选，在 seeds 42、43、44 上分别运行 1,600 步，共 4,800 步。
3. Teacher 采集：最佳候选运行剩余 3,800 步；采集完整状态、任务特征、43 维动作、MPC 可行率和安全事件。
4. 离线训练：使用采集数据训练 deterministic z16/latent action model。离线优化步不计入 Isaac Sim 10,000 步预算。

每个仿真实例必须记录实际消耗步数。提前失败的未用步数回收到 teacher 采集阶段，确保最终累计不超过 10,000。

## 候选与选择规则

基线为现有实现。四个候选为：完整 SO(3) 修复默认参数、降低第一节点角速度上限、提高姿态轨迹时间缩放、组合前两项的保守配置。

任何候选出现非有限值、硬关节限位、意外 reset 或安全拒绝即判失败并停止。其余候选按以下顺序比较：Arm MPC 最小可行率、Hand MPC 最小可行率、最大首节点隐含纠偏角速度、保持姿态误差、相对掌面滑移。只允许一个候选进入跨 seed 阶段。

## 资源隔离

- 只使用当前空闲 GPU 4–7；不占用 GPU 0–3。
- 每个 Isaac Sim 进程设置独立 `CUDA_VISIBLE_DEVICES`、日志目录和 artifact 文件名。
- 并行进程数最多 4；单进程只创建计划要求的环境数。
- 启动前再次检查显存；若目标 GPU 剩余显存低于 18 GiB，则不启动并等待资源变化。
- 不终止、不修改其他用户进程。

## 完成标准

- 新增纯控制单元测试覆盖非单位姿态、跨接近 pi 边界的插值和角速度一致性。
- 350 步复现中不再在第 184 步出现原姿态表示不一致导致的 Arm 不可行。
- 最佳候选完成三个 1,600 步 seed，无非有限值、硬限位、意外 reset 或安全拒绝。
- 总仿真步数不超过 10,000，全部运行产物可追溯。

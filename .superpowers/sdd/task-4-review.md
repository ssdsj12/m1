# Task 4 Independent Review

## Spec Compliance

- `M1_PANDA_CFG` uses the repository-local combined USD and declares the required `BASE_LINK`, `panda_link0`, and 25-DOF constants.
- The Panda initial state exactly matches the installed IsaacLab Franka legal home pose. The shoulder (`panda_joint[1-4]`), forearm (`panda_joint[5-7]`), and hand (`panda_finger_joint.*`) actuator groups and their effort/velocity/stiffness/damping values match the installed `isaaclab_assets.robots.franka.FRANKA_PANDA_CFG`.
- `M1_CFG.copy()` is effectively deep for these config objects. In the installed loco IsaacLab, `configclass.copy()` calls `dataclasses.replace()`, and the reconstructed config's injected post-init deep-copies every non-callable field. The reported real AppLauncher import additionally observed distinct nested `spawn`, `init_state`, and `actuators` state with the original M1 values unchanged. The implementation therefore does not currently contaminate `M1_CFG` through nested mutation.
- The policy's only joint-valued observations are `joint_pos_rel` and `joint_vel_rel`, and each explicitly selects exactly `M1_JOINT_NAMES`. `last_action` is generated by an action config containing only the M1 terms.
- Actions are in the required declaration order: 12 M1 leg joint position actions followed by four M1 wheel joint velocity actions. Their scale, default-offset behavior, and clip values exactly match the plan. No Panda joint appears in either action term.
- The Task 4 implementation does not introduce mount-wrench, IK, OSC, or training behavior.
- The Gym ID spelling and entry point text are exact, and the new registration does not alter any existing registration declarations. However, the new ID is not reachable through the real default package import chain; see Important issue 1.
- Git is genuinely unavailable (`/home/xk/coding/M1` is not a Git worktree), and the report/log/dashboard consistently record that fact and distinguish the isolated import from an unperformed physics environment step.
- Not creating/stepping a physics environment is consistent with Task 4's explicit Step 5 static acceptance command; Task 3 already supplied combined-asset physics evidence. It remains a stated runtime limitation, not a Task 4 spec violation by itself.

## Strengths

- The implementation is narrowly scoped to the four planned Task 4 code/test surfaces and keeps Task 5+ concepts out.
- The combined config preserves the existing M1 rigid/articulation properties and M1 initial pose while adding only the local USD substitution, Panda defaults, and Panda hold actuators.
- The observation override avoids the common inheritance error where the parent smoke config would expose all 25 articulation joints.
- The action declaration is exact, ordered, and excludes Panda; the reported real config import confirmed dimensions `(12, 4)` and 16 selected observation joints.
- Reporting is unusually candid about the default registration-chain blocker and the absence of an environment physics step rather than overstating the isolated import evidence.

## Issues

### Critical

None.

### Important

1. **The produced Gym ID is unavailable through the repository's real public import path.** `go2_pvcnn.tasks` imports the monolithic registration module ([`Go2Pvcnn/go2_pvcnn/tasks/__init__.py:4`](../../Go2Pvcnn/go2_pvcnn/tasks/__init__.py)), and that module imports `m1_small_obstacle_env_cfg` before executing any `gym.register` call ([`Go2Pvcnn/go2_pvcnn/tasks/register_m1_envs.py:10`](../../Go2Pvcnn/go2_pvcnn/tasks/register_m1_envs.py)). In the installed loco IsaacLab, the latter fails on the unavailable `MultiMeshRayCasterCfg` import ([`Go2Pvcnn/go2_pvcnn/tasks/m1_small_obstacle_env_cfg.py:11`](../../Go2Pvcnn/go2_pvcnn/tasks/m1_small_obstacle_env_cfg.py)). Although the incompatibility predates Task 4, its effect is directly on a Task 4 output: execution never reaches the new registration at `register_m1_envs.py:151`, so normal callers cannot obtain `gym.spec("Isaac-M1-Panda-Smoke-v0")`. The isolated namespace import only proves the config module can instantiate; it does not register the ID. Within Task 4 scope, decouple the Panda smoke registration from the incompatible obstacle imports (or otherwise make the normal registration chain complete) while preserving all old IDs and their behavior, then verify the real package import followed by `gym.spec`.

2. **The new tests do not falsify most of the strict Task 4 contract.** The main test only searches source tokens for constants, joint-list expressions, and the ID ([`Go2Pvcnn/tests/test_m1_panda_smoke_cfg_static.py:59`](../../Go2Pvcnn/tests/test_m1_panda_smoke_cfg_static.py)); it would still pass with wrong action classes, order, scales, offsets, clips, Panda actuator limits/groups, or home pose. The observation test independently checks two selector tokens and two function-name tokens ([`Go2Pvcnn/tests/test_m1_panda_smoke_cfg_static.py:73`](../../Go2Pvcnn/tests/test_m1_panda_smoke_cfg_static.py)), so it does not prove that each joint observation owns one M1 selector or that no additional all-joint observation exists. Add AST or instantiated-config assertions covering exact term order/type/parameters and exact observation-term-to-selector binding, plus exact Panda home/actuator values. Also add a real registration-chain assertion as described above.

### Minor

1. **The copy-isolation unit test proves the stub's semantics, not IsaacLab's.** `_Cfg.copy()` is defined as `copy.deepcopy()` by the test itself, so the identity assertions at [`Go2Pvcnn/tests/test_m1_panda_smoke_cfg_static.py:82`](../../Go2Pvcnn/tests/test_m1_panda_smoke_cfg_static.py) cannot catch a change in IsaacLab `configclass.copy()`. This is not a current implementation defect: installed-source inspection shows that the real `replace()` reconstruction triggers the injected deep-copy post-init, and the recorded AppLauncher import agrees. Still, the regression should either exercise the installed configclass or explicitly test the source-backed behavior without substituting the method under test.

2. **No ManagerBasedRLEnv construction or step was performed.** This is outside the plan's explicit static acceptance and is accurately disclosed, so it is not grounds for rejection alone. Once the registration-chain issue is fixed, a bounded create/reset/one-step smoke would close the remaining “runnable” evidence gap.

## Assessment

**Not approved.** The config implementation itself is spec-correct, but a required produced interface—the Gym ID—is not available through the actual package import chain, and the new regression tests do not enforce several binding action/observation/actuator contracts.

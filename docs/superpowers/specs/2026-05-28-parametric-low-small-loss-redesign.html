Parametric MPC low-small loss 重构设计

日期：2026-05-28 ｜ 主线：T302k parametric MPC trajectory contract ｜ 文件范围： Go2Pvcnn/extension/batch_mpc_planner

1. 设计目标

当前目标是重构 MPC 跨 low-small 小障碍物相关 loss，使优化逻辑更清楚，并避免 touchdown 落在 small obstacle 上、swing/FK 轨迹扫到障碍、IK/FK 实际轨迹和规划轨迹偏差过大、以及平面小障碍场景里 root z 被障碍高度抬起来。

这次设计只针对 parametric MPC 主线。decode_parametric_trajectory() 继续只消费 nominal 和 variables，并输出轨迹；它不做语义硬修正、不做 touchdown hard projection、不做足端硬分离。

调试边界：后续调试只能调本设计确认的 loss 权重和参数。不得新增硬约束。若需要新增任何 loss，必须先和用户确认。

2. 删除和替换范围

旧的 low-small / touchdown 相关 loss 职责混杂，需要删除或替换：

  • _parametric_low_small_crossing_loss
  • _parametric_touchdown_semantic_ground_loss
  • _parametric_touchdown_spacing_loss

保留已有 parametric contract：

  • touchdown 的 z 继续由 height_at(terrain, touchdown_xy) hard ground。
  • nominal 构建仍在 semantic_policy.py，decode 不负责语义 command shaping。
  • 优化循环里只通过 loss 改变 variables。

3. 新 loss 集合

编号 名称 作用 是否参与优化
0 plane low-small FK 语义碰撞测试 只做测试/诊断，检测 target 触发腿和 IK/FK 后几何碰撞 否

4. 第 0 条：plane low-small FK 语义碰撞测试

第 0 条不进入 loss，只作为后续调试和验收测试。它只在 IsaacLab 创建出来的 plane/flat terrain 上执行。

4.0 测试运行环境

第 0 条测试必须使用真实 IsaacLab 环境执行，不能只用本地纯单元测试代替。指定环境为：

/mnt/mydisk/lhy/anaconda3/envs/env_isaacsim/bin/python

机器有四张 GPU，测试时用 CUDA_VISIBLE_DEVICES 选择要占用的卡。例如：

CUDA_VISIBLE_DEVICES=0 /mnt/mydisk/lhy/anaconda3/envs/env_isaacsim/bin/python ...

不同方向/速度的大批量测试可以分配到不同卡上跑，但每条测试日志必须记录使用的 CUDA_VISIBLE_DEVICES、命令速度、terrain 类型、horizon 和 replan 次数。

4.1 target 触发腿检测

使用当前 target_foot_pos 的 25 帧轨迹，不额外插值。对每条腿每帧 foot XY 做横向 probe，查询 semantic == 1。

p_probe(t,l,i) = target_foot_xy(t,l) + delta_i * lateral_axis delta_i ∈ [-probe_half_width, ..., +probe_half_width] 如果任意 sem(p_probe) == 1，则该腿 crossing_leg_mask[l] = 1

测试参数：

  • low_small_semantic_probe_half_width_m
  • low_small_semantic_probe_count

4.2 触发腿 FK 语义碰撞检测

只对 crossing_leg_mask == 1 的腿，检查 IK 后 FK 的实际几何轨迹。检查对象包括：

  • fk_foot_pos
  • fk_knee_pos
  • fk_shank_samples，即 foot 到 knee 之间采样点
  • fk_root_pos
  • fk_root_underbody_samples

碰撞定义：

sem(point_xy) == 1 且 point_z < height(point_xy)

4.3 每个速度和方向都要测试

至少覆盖：

  • forward / backward
  • left / right 横移
  • turn_left / turn_right
  • diag_fl / diag_fr
  • mixed_turn_l / mixed_turn_r

每个方向都要覆盖单次 plan 和多次 replan，horizon 为 25。

  • crossing_leg_count

  • fk_semantic_collision_rate

  • fk_semantic_collision_by_leg
  • fk_semantic_min_clearance_over_semantic_m

4.4.1 指标计算方法

指标中文含义计算方法
plane_env_count 本次测试中属于 IsaacLab plane/flat terrain 的 env 数量。 对自动得到的 plane_mask 求和：sum(plane_mask)。
crossing_leg_mask 每条腿是否被 target 足端轨迹触发 low-small crossing。 对每条腿 25 帧 target foot XY 加横向 probe 后查 semantic == 1；任意帧任意 probe 命中则该腿为 1。
crossing_leg_count 触发 crossing 的腿数量。 sum(crossing_leg_mask)。如果为 0，本条命令不能证明跨越成功，只能记为未覆盖。
fk_semantic_collision_count 触发腿关联的 FK 几何点发生语义碰撞的次数。 在触发腿上统计所有 foot/knee/shank/root/underbody 点；同时满足 sem(point_xy)==1 且 point_z < height(point_xy) 的点数。
fk_semantic_collision_rate FK 语义碰撞比例。 fk_semantic_collision_count / checked_point_count，其中 checked_point_count 是触发腿相关的全部被检查几何点数量。
fk_semantic_collision_by_part 按几何部位统计碰撞次数。 分别对 foot、knee、shank、root、underbody 应用同一个碰撞定义并求和。
fk_semantic_collision_by_leg 按腿统计碰撞次数。 只统计 crossing_leg_mask == 1 的腿；root/underbody 属于 body，可单独记录或复制到触发腿关联统计中，但日志要说明采用方式。
fk_semantic_min_clearance_over_semantic_m FK 几何点在 small obstacle 语义区域上的最小净空。 只在 sem(point_xy)==1 的检查点上计算 point_z - height(point_xy)，取最小值。小于 0 表示穿入地形/障碍。
fk_semantic_first_collision_frame 第一次 FK 语义碰撞发生的帧号。 在 25 帧中找最早满足碰撞定义的帧；如果没有碰撞，记录为 -1 或 null。
planned_vs_fk_foot_error_mean_m 规划足端和 IK/FK 实际足端的平均偏差。 对所有 env、25 帧、4 条腿计算 ||target_foot_pos - fk_foot_pos|| 后求平均。
planned_vs_fk_foot_error_max_m 规划足端和 IK/FK 实际足端的最大偏差。 对所有 env、25 帧、4 条腿的 ||target_foot_pos - fk_foot_pos|| 取最大值。
planned_vs_fk_foot_error_by_leg_mean_m 每条腿的规划/FK 平均偏差。 固定腿编号，对 env 和 25 帧上的 ||target_foot_pos - fk_foot_pos|| 求平均。
planned_vs_fk_foot_error_by_leg_max_m 每条腿的规划/FK 最大偏差。 固定腿编号，对 env 和 25 帧上的 ||target_foot_pos - fk_foot_pos|| 取最大值。
planned_vs_fk_foot_error_crossing_leg_mean_m 触发 crossing 的腿上的规划/FK 平均偏差。 只保留 crossing_leg_mask == 1 的腿，对其 25 帧误差求平均。
planned_vs_fk_foot_error_crossing_leg_max_m 触发 crossing 的腿上的规划/FK 最大偏差。 只保留 crossing_leg_mask == 1 的腿，对其 25 帧误差取最大值。

4.5 通过条件

plane_env_count > 0 crossing_leg_count > 0 fk_semantic_collision_count == 0 fk_semantic_collision_rate == 0 fk_semantic_min_clearance_over_semantic_m >= 0 planned_vs_fk_foot_error_crossing_leg_max_m <= 测试阈值

规划足端和 FK 足端偏差阈值先作为测试阈值，不作为 loss 参数。建议第一版用 0.05m；如果太严，调到 0.08m。

5. 第 1 条：touchdown keepout loss

5.1 触发逻辑

先直接查询每条腿 touchdown 的语义：

s_l = sem(touchdown_xy_l)

只有当 s_l != 0 时，该腿才进入后续 keepout 计算。如果 touchdown 当前不在语义物体上，这条腿该 loss 为 0。

5.2 low-small 圆形近似

对 height/semantic map 中 semantic == 1 的点按栅格连通性分连通域。连续区域拟合一个圆，不连续区域拟合多个圆。连通性尺度跟雷达/height map 分辨率一致，不做人为跨格桥接。

圆形近似必须尽量快，并且应优先使用 GPU tensor 计算。不得把每个 env 的 semantic map 搬到 CPU 后用 Python 循环做连通域和拟合。实现时应使用 torch / CUDA 上的批量张量操作，必要时只对小批量候选区域做有限循环，但数据仍保持在 GPU。

每个连通域得到：

  • 圆心 c_k
  • 半径 r_k

圆心可用连通域点的均值或 bbox 中心；半径用连通域点到圆心的最大距离。

快速 GPU 实现建议：

  • 先在 GPU 上得到 small_mask = semantic_map == 1。
  • 利用栅格邻域传播、形态学膨胀/腐蚀或固定上限的 connected-component 近似，把不连续区域拆成多个 component。
  • 对每个 component 在 GPU 上计算 bbox 或均值圆心。
  • 半径用 component 内点到圆心的最大 XY 距离，仍在 GPU 上用 reduction 得到。
  • 如果实现上需要 component 数量上限，应记录上限并在测试日志输出是否发生截断。

5.3 loss 公式

对触发的 touchdown，找到对应或最侵犯的 low-small 圆：

L_td,l = ReLU(r_k + touchdown_keepout_radius_extra_m - ||td_l - c_k||)^2

最终对四条腿平均，未触发腿贡献 0。

5.4 参数

参数含义
touchdown_keepout_radius_extra_m 拟合圆半径之外再额外扩多少。它同时补偿语义图/雷达分辨率误差和 touchdown 安全边界。

6. 第 2 条：swing foot terrain clearance loss

这条不区分语义和地形。只要是 swing 点，就检查 target foot 是否高过当前位置 height map。

L_swing = mean_{t,l}( swing_prob(t,l) * ReLU(height(foot_xy(t,l)) + swing_foot_clearance_margin_m - foot_z(t,l))^2 )

这条统一覆盖普通地形、low-small 障碍、台阶等，只依赖 height map。

参数含义
swing_foot_clearance_margin_m swing target foot 高过当前位置地形的最小余量。

7. 第 3 条：FK body/leg terrain collision loss

这条检查 IK 后再 FK 出来的实际几何点，不只看 FK foot。所有检查点统一和 height map 比较。

检查对象：

  • fk_foot_pos
  • fk_knee_pos
  • fk_shank_samples：foot 到 knee 之间采样点
  • fk_root_pos
  • fk_root_underbody_samples
L_point = ReLU(height(point_xy) + margin_part - point_z)^2

各 part 的 loss 按权重汇总。语义障碍如果体现在 height map 中，会自然被这条抓到。

参数含义
fk_foot_clearance_margin_mFK foot 离 height map 的最小余量。
fk_knee_clearance_margin_mFK knee 离 height map 的最小余量。
fk_shank_clearance_margin_mfoot-knee 连杆采样点离 height map 的最小余量。
fk_root_clearance_margin_mroot 几何点离 height map 的最小余量。
fk_underbody_clearance_margin_mroot 下方 underbody 采样点离 height map 的最小余量。
fk_shank_sample_countfoot 到 knee 之间采样点数量。
fk_underbody_sample_countroot underbody 采样点数量。

8. 第 4 条：optimized vs IK/FK trajectory consistency loss

这条不只比 touchdown，而是比较全部 25 帧规划足端轨迹和 IK/FK 后实际足端轨迹。

8.1 world-frame foot consistency

L_abs = mean_{t,l}( || foot_opt(t,l) - foot_fk(t,l) ||^2 )

8.2 root-relative foot consistency

foot_opt_rel = R(root_rpy(t))^T * (foot_opt(t,l) - root_pos(t)) foot_fk_rel = R(root_rpy(t))^T * (foot_fk(t,l) - root_pos(t)) L_rel = mean_{t,l}( || foot_opt_rel - foot_fk_rel ||^2 )

8.3 总项

L_traj_consistency = L_abs + L_rel

这条除了整体权重，不新增参数。

9. 第 5 条：plane terrain root z target loss

这条只在 IsaacLab 创建出来的 plane/flat terrain 上启用。row 是难度，不参与判断；不手动传 terrain col。

实现上应从 IsaacLab terrain type 自动得到 plane_mask。如果当前 MpcPlannerTerrain 没有这个信息，需要在构建 terrain 时补一个内部字段，例如 is_plane_terrain。这个字段不是用户调参。

L_root_z_plane = plane_mask * mean_t( (root_z(t) - root_z_target_height_m)^2 )
参数含义
root_z_target_height_m root z 目标高度，默认初始化为当前初始状态 root 高度。

11. 实现流程约束

  1. semantic_policy.py 继续负责 nominal 和 high/large command shaping。
  2. decode_parametric_trajectory() 只根据 nominal 和 variables 生成轨迹，不做语义 hard projection。
  3. loss 阶段计算 target trajectory、IK、FK、碰撞和一致性项。
  4. touchdown z 仍由 height map hard ground。
  5. 新增 plane/flat terrain mask 信息时，应从 IsaacLab terrain 创建结果自动推导，不作为用户手动传入的 terrain col 参数。

12. 禁止项

  • 禁止新增 decode-time touchdown hard projection。
  • 禁止直接修正 touchdown 到合法点。
  • 禁止 hard separation 四足落点。
  • 禁止优化后把 foot/root snap 到合法区域。
  • 禁止在未和用户确认前新增本设计以外的 loss。

13. 验收重点

  • plane/flat terrain 上，每个速度和方向的 low-small crossing 测试都要覆盖。
  • 触发 crossing 的腿，IK/FK 后 foot/knee/shank/root/underbody 不应和 semantic == 1 且 height map 发生碰撞。
  • 输出规划足端和 FK 足端偏差，避免“没有碰撞只是因为 FK 偏离规划”的假成功。
  • 横移、转弯、多次 replan 是重点，因为之前这些方向更容易出现足端乱飞和累计误差。

14. 自查结论

本设计没有引入未确认的硬约束；第 0 条只作为测试，不参与 loss；第 4 条不加额外参数；第 5 条不使用手动 terrain col 参数，而是要求从 IsaacLab plane/flat terrain 信息自动得到 mask。

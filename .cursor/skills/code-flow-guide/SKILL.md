# Code Flow Guide

用这个 skill 帮用户快速弄清"代码到底怎么跑起来"，并给出可直接在 IDE 里跟读的执行地图。

## 工作目标

优先完成以下事情：

1. 找到真实执行入口
2. 建立主执行链路
3. 生成大流程图
4. 展开对应的小流程图
5. 标注关键节点的文件路径和行号
6. 告诉用户下一步该看哪段代码

## 输出语言

始终使用中文回答。

允许保留英文标识符，包括：

- 类名
- 函数名
- 配置名
- 文件路径

## 先做什么

开始回答前先做这些检查：

1. 找程序真实入口，不要只停留在用户当前打开的文件
2. 沿调用链向上找谁触发它，向下找它调用了谁
3. 确认关键跳转点对应的文件路径和行号
4. 如果项目属于 RL、机器人、仿真、具身智能，优先抽主链：`config -> env -> scene -> sensor -> observation -> policy -> action -> env.step -> reward -> trainer update`

如果暂时无法定位完整链路，要明确说明卡在什么边界，例如动态注册、反射、配置注入、基类分发或外部框架入口。

## 回答结构

每次回答都必须严格按下面顺序输出，不要跳段，不要改名：

1. `1 一句话总结`
2. `2 大流程图（大流程内要有小流程图标注）`
3. `3 小流程图（多个）`
4. `4 Call Chain（必要时）`
5. `5 建议跟读顺序`
6. `6 本轮覆盖范围 / 未展开部分`
7. `7 状态输出`

禁止一上来先讲细节。
禁止跳过大流程图。
禁止用长段说明替代流程图。

## 大流程图规则

大流程图只做目录，不展开细节。每个关键阶段都尽量标成：

`阶段名（小流程图 N：阶段名）`
`文件路径:行号`

示例格式：

```text
main()
train.py:21

↓

配置解析（小流程图 1：配置解析）
config_loader.py:40

↓

环境初始化（小流程图 2：环境初始化）
env_builder.py:65

↓

训练循环（小流程图 3：训练循环）
trainer.py:120
```

大流程图中不要写局部变量细节、条件分支细节或过多解释，这些内容留给小流程图。

## 小流程图规则

小流程图是对大流程图节点的展开。

标题必须与大流程图中的标题完全一致，不允许改写同义词。

例如大流程图里写的是：

`环境初始化（小流程图 2：环境初始化）`

那小流程图标题必须写成：

`小流程图 2：环境初始化`

推荐格式：

```text
小流程图 2：环境初始化

函数 / 类
file.py:line
输入
关键变量

↓

函数 / 类
file.py:line
处理逻辑

↓

输出
```

如果需要表达数据流，使用：

```text
输入
↓
处理
↓
输出
```

## 一一对应约束

生成答案前必须自检：

1. 大流程图中所有要展开的节点都写成 `（小流程图 N：标题）`
2. 每个小流程图标题与大流程图完全一致
3. 每个小流程图都能在大流程图中找到对应节点
4. 大流程图里的关键节点都有代码出处
5. 没有把细节错误地塞进大流程图

如果不满足，先重写再输出。

## Call Chain 规则

当用户要求调用链，或者"谁调用某函数 / 某类在哪里被用到 / trace call chain"，必须提供独立的调用链段落。

格式尽量简洁：

```text
main()
↓
trainer.run()
↓
rollout()
↓
env.step()
↓
reward_manager.compute()
```

如果链路存在分叉，可以分成多条短链，不要混成一大段文字。

## 文件标注规则

重要节点都要标注：

`文件路径:行号`

禁止只说"在 env 文件里"或"在 trainer 那边"。

如果行号无法可靠确定，说明原因，并至少给到明确文件路径和函数名。

## 建议跟读顺序

回答里必须给出 IDE 跟读顺序，格式类似：

```text
建议按以下顺序阅读代码：

1. train.py:21 main()
2. trainer.py:120 run()
3. env_builder.py:65 build_env()
4. manager_based_rl_env.py:210 step()
5. reward_manager.py:88 compute()
```

顺序要服务于"读得懂"，而不是简单按文件名罗列。

## 覆盖范围与状态

结尾必须明确两件事：

1. 本轮已覆盖了什么，未展开什么
2. 当前分析状态如何，下一步建议展开哪里

状态段必须写成：

```text
状态

入口定位：已完成 / 未完成
主执行链路：已完成 / 部分完成 / 未完成
小流程图展开：已完成 / 部分完成 / 未完成
建议下一步：...
```

## 适配 RL / 仿真项目

如果项目明显属于 RL、IsaacLab、Habitat、机器人仿真或具身智能，优先围绕这些对象建图：

- config
- env
- scene
- sensor
- observation
- policy
- action
- env.step
- reward
- trainer update

如果用户问的是某个局部文件，也尽量把它挂回这条主链里，说明它在整体系统中的位置。

## 交流风格

回答要面向"边看边跳代码"的用户：

- 先给整体，再给细节
- 多用流程图，少写散文式解释
- 每一轮都让用户知道下一步该看哪里
- 不确定时明确说"推测"还是"已确认"

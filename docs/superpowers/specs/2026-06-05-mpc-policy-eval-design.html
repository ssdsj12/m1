MPC Policy 评估脚本设计

日期：2026-06-05 ｜ 主线：Teacher elevation trajectory MPC semantic 评估 ｜ 目标入口： Go2Pvcnn/scripts/mpc_policy_eval.py

1. 背景和目标

当前仓库已经把普通 policy playback 和 MPC viewer 拆开：scripts/play.py 使用 no-MPC 的 PLAY 配置，extension/viz/go2_foostep_planner.py 使用 MPC-enabled 的 VIEWER 配置。这次新增的不是普通播放入口，而是一个专门的 policy 评估入口，用于加载训练权重，并在真实 IsaacLab rollout 中启用 MPC reference/cache。

评估脚本需要覆盖两个测试内容：

  • tracking：在不同地形上运行 policy，比较 MPC 规划出的足端参考轨迹和 policy 实际足端轨迹。
  • small_collision：在大量 small semantic obstacles 的平地上，给 Go2 输入不同速度方向，按环境统计真实语义碰撞率。
本设计不修改 scripts/play.py 的 no-MPC 合约，不新增 shell 启动脚本，不把评估逻辑塞进 viewer。新增入口只放在 Go2Pvcnn/scripts/mpc_policy_eval.py。

2. 总体方案

新增一个 Python 脚本：

Go2Pvcnn/scripts/mpc_policy_eval.py

它负责启动 IsaacLab、构造评估环境、加载 RSL-RL policy checkpoint、同步速度命令到 policy 和 MPC runtime、采集指标、输出 JSONL 和 summary。脚本提供两个 mode：

Mode用途核心数据源主指标
tracking 不同地形上评估 policy 是否能跟踪 MPC foot reference MPC reference cache + Isaac robot body positions 实际足端 vs MPC 参考足端误差
small_collision 大量 small 语义障碍物平地上评估真实碰撞率 semantic_contact_small.data.force_matrix_w 每轮发生过碰撞的 env 数 / env 总数

--headless 和 --livestream 2 使用同一套 rollout 和统计逻辑。headless 用于自动跑指标；livestream 用于 WebRTC 可视化查看，同时仍然写出同样的指标文件。

3. 环境配置

3.1 Tracking Eval 配置

新增或等价构造 TeacherElevationTrajectoryMpcSemanticTrackingEvalEnvCfg。它应启用 MPC reference/cache，用于真实 policy rollout 中的 reference 生成和指标对比。

  • planner_owned_reference_cache=True
  • use_batched_reference_trajectory=True
  • planner_backend="mpc"
  • 保留 reference_foot_pos reward/cache 路径，保证 MPC reference 可用。
  • 地形使用当前任务的 row-gated terrain；通过 CLI 选择 terrain_rows / terrain_cols 做分组评估。
  • 不改变当前 MPC loss，不添加新 loss，不恢复旧 dense residual 路线。

3.2 Small Collision Eval 配置

新增或等价构造 TeacherElevationTrajectoryMpcSemanticSmallCollisionEvalEnvCfg。它用于平地上密集 small semantic obstacles 的真实 contact 碰撞率评估。

  • 强制选择 flat/plane terrain。
  • small semantic object 数量由 --small-count-per-tile 控制。
  • large semantic object 默认置为 0，避免污染 small collision 统计。
  • 保留 semantic_contact_small sensor，并可保留 semantic_contact_large 作为配置检查。
  • 碰撞主指标只来自真实 PhysX contact，不用高度图几何近似替代。

4. 命令行参数

参数默认值说明
--mode {tracking,small_collision}必填选择评估内容。
--run-dir必填RSL-RL run 目录名。
--checkpoint必填checkpoint 文件名，例如 model_14000.pt。
--num-envs1并行环境数；headless 可用 64/128，livestream 建议 1。
--num-rounds1评估轮数。
--max-steps1000每轮执行的 env step 数。执行完 max_steps 算一轮。
--devicecuda:0IsaacLab 内部 device。
--headless来自 AppLauncher无界面自动评估。
--livestream 2来自 AppLauncherWebRTC 可视化查看。
--terrain-rows0,3,6,9tracking mode 的 terrain row 列表。
--terrain-cols0tracking mode 的 terrain col 列表。
--command-mode {fixed,random,sweep}fixed速度命令来源。
--command "vx vy yaw"0.4 0.0 0.0fixed mode 下的 body-frame 命令。
--command-sweep空sweep mode 的命令列表，例如 "0.4 0 0;0 0.3 0;0.3 0 0.5"。
--random-command-interval100random mode 每隔多少 step 换一次速度方向。
--small-count-per-tile80small_collision mode 每个 flat tile 的 small 物体数量目标。
--collision-force-threshold1.0真实 contact 判定阈值。
--output-dir必填输出 metrics.jsonl、rounds.jsonl、summary.json。
自动统计模式要求 --max-steps > 0。--max-steps 0 只用于 livestream/manual 查看，因为它没有明确的轮结束条件。

6. Livestream 可视化语义

可视化模式下，同一个 body-frame 速度命令必须同时输入给 policy command manager 和 MPC planner/runtime。这样画面中比较的是同一速度目标下的两条轨迹，而不是 policy 和 MPC 各自收到不同命令。

command source -> policy command manager -> MPC trajectory manager / planner cfg

画面中显示两类足端信息：

  • MPC 参考足端轨迹：从 _trajectory_reference_cache.foot_pos_w 或 manager 当前 cache 中读取，并用 marker 画出未来足端轨迹。
  • Policy 实际足端轨迹：从 Isaac robot body positions 读取真实 feet world position，可显示当前实际足端点和短历史轨迹。

marker 风格复用 extension/viz/go2_foostep_planner.py 的足端轨迹思路：四条腿用不同颜色或稳定 marker namespace，必要时叠加当前 reference frame 小球和实际 foot 小球。

7. Tracking 指标

7.1 主指标

指标定义用途
foot_tracking_error_mean_m 实际足端 world position 与 MPC reference foot_pos_w 的 L2 误差均值。 整体足端跟踪质量。
foot_tracking_error_p95_m 足端 L2 误差 95 分位。 发现均值掩盖的尖峰偏差。
per_leg_foot_error_mean_m FL/FR/RL/RR 分腿足端误差均值。 定位单腿系统性问题。
reference_valid_ratio MPC reference cache 有效比例。 先确认 planner/cache 没坏。
episode_alive_ratio rollout 中没有提前 reset/fall 的比例。 过滤摔倒导致的异常 tracking 结果。

7.2 诊断指标

  • root_xy_error_mean_m：实际 base xy 与 MPC root reference 的误差。
  • root_yaw_error_mean_rad：实际 yaw 与 MPC yaw reference 的误差。
  • joint_error_mean_rad：实际关节角与 reference joint 的误差。
  • contact_match_rate：实际接触状态与 MPC contact schedule 的匹配率。
  • command_tracking_error_mean：实际 base velocity 与输入 command 的误差。
  • replan_count / planner_fail_count：MPC runtime 稳定性。
  • 按 terrain_row、terrain_col、terrain_name 分组输出。

8. Small Collision 指标

8.1 主指标

主指标按环境计数，而不是按 step 计数。一轮内某个 env 只要任意时刻发生过 small semantic contact，这个 env 就记为碰撞 1 次；同一个 env 碰 1 次和碰 20 次，主指标都只算 1 个 collided env。

small_collision_env_rate_per_round = collided_env_count / num_envs
指标定义说明
collided_env_count 当前轮中发生过至少一次 small contact 的 env 数。 每个 env 每轮最多计 1。
small_collision_env_rate_per_round collided_env_count / num_envs 该轮主碰撞率。
aggregate_small_collision_env_rate sum(collided_env_count) / (num_rounds * num_envs) 所有轮的总体碰撞率。

示例：num_envs=64，一轮 max_steps=1000，其中 7 个 env 在任意 step 碰过 small obstacle，则这一轮碰撞率是 7 / 64 = 10.94%。

8.2 诊断指标

  • first_collision_step_by_env：每个碰撞 env 第一次碰撞 step。
  • collision_body_names_by_env：每个碰撞 env 触发 contact 的 body 名称集合。
  • round_small_force_max：该轮 small contact 最大力。
  • distance_traveled_m_by_env：每个 env 的行走距离，防止没走动导致假低碰撞率。
  • collision_by_command_bin：按速度方向/速度大小分组的碰撞 env rate。
  • large_collision_env_count：large contact 诊断计数；small_collision 环境中应为 0 或接近 0。
  • semantic_contact_sensor_valid：确认 force_matrix_w shape 非空且无 NaN/Inf。

9. 输出文件

每次运行在 --output-dir 下创建一个带时间戳的 run 子目录，避免覆盖历史结果。

文件内容
metrics.jsonl 按 step 或采样间隔写轻量记录，包括 round、step、command、部分 tracking/collision 即时指标。
rounds.jsonl 每轮一条 summary，包括主指标、诊断指标、环境数、步数、terrain/command 分组。
summary.json 所有 rounds 的 aggregate，包括 mean/p95/max、按地形和命令分组的统计。
config.json 完整 CLI 参数、checkpoint 路径、git ref、环境配置摘要。

10. 验收标准

第一版评估先建立 baseline，不直接设定严格的 performance 门槛。必须满足的硬条件是：

  • checkpoint 能加载，policy 能进入 rollout。
  • tracking mode 下 MPC reference/cache 有效，reference_valid_ratio 可计算。
  • small_collision mode 下 semantic_contact_small.force_matrix_w shape 非空、有限，且能按 env 聚合。
  • headless 模式能跑完 num_rounds * max_steps。
  • livestream 模式下同一个 command 同时输入 policy 和 MPC，并能看到 MPC foot reference marker。
  • 所有输出文件稳定落盘，无 NaN/Inf 主指标。
后续可以基于 baseline 再设硬阈值，例如 tracking p95 足端误差上限或 small collision env rate 上限。第一版目标是把真实评估链路和指标口径固定下来。

11. 实现边界和风险

  • 不得恢复旧的 batched_planner / dense residual 路线；当前目标是 extension/batch_mpc_planner。
  • 不得修改 scripts/play.py 的 no-MPC 行为。
  • 不得把真实碰撞率替换为语义高度图近似。
  • 如果新增 eval cfg，改动范围限制在任务配置、脚本入口和必要测试；不调整 MPC loss。
  • livestream 可视化依赖 IsaacLab AppLauncher WebRTC 参数，需沿用现有 viewer/play 的 --livestream 2 处理习惯。
  • 多 env headless 指标应避免每 step 大量 CPU 同步；可按固定 interval 写 metrics.jsonl，但 round summary 必须完整。

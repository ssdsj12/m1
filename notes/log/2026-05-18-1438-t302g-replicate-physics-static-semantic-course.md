## Purpose

Allow the independent MPC semantic RL task to use `replicate_physics=True` while keeping semantic obstacles as a global static course visible to the semantic scanner before sensor initialization.

## Input Conditions

- Semantic course is generated by `SemanticCourseTerrainImporter`, immediately after terrain generation and before sensors initialize.
- T302g scene uses `replicate_physics=True`.
- T302g event cfg sets `generate_semantic_course = None`; semantic course no longer uses `prestartup` or `startup`.
- Smoke run maps physical GPU1 to process `cuda:0` with `CUDA_VISIBLE_DEVICES=1` because physical GPU0 was almost full.

## Result

Partial pass. The scene/semantic scanner part is fixed: semantic mesh exists before scanner initialization while `replicate_physics=True` is active. The smoke run then hits a separate MPC CUDA OOM during `high_obstacle_avoidance_loss` after entering training.

## Conclusion

The original scene replication blocker is removed for T302g by moving semantic-course generation out of EventManager and into the terrain-importer path. The remaining 4096 blocker is no longer the prestartup/replication conflict; it is MPC memory/throughput under the full semantic scene.

## Follow-Up

- Continue optimizing MPC heavy loss memory/compute, especially `high_obstacle_avoidance_loss` and other semantic terrain loss tensors.
- Re-run 4096 only after MPC memory pressure is reduced or after a smaller selected planning batch is proven not to degrade backlog/collect time.
- Keep `CUDA_VISIBLE_DEVICES` caveat in mind: physical GPU0 is currently near full and causes Omniverse/Warp initialization noise even when `--device cuda:1` is passed.
